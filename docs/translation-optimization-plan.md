# 翻译优化：范围冻结与后续验收

基线1.1.0（14c9835），候选交付1.2.0-rc.1。本文保留开发方向与转正门槛；当前已实现机制、限额与测试数字统一见[翻译策略与验收](quality-tier.md)，不将设计目标冒充实际收益。

## 目标

快速档提高第一次翻译的可靠性，不追求继续提速，也不增加固定模型轮次；标准质量保持有限重点审校；精修允许用户投入更多时间和算力，但必须有终点、可取消、可恢复。网络资料和已有译文只能作可追溯参考，不代替原文。

两个顶层档位保持快速/质量；质量内部选择标准/精修。旧配置不自动升级到昂贵方案，联网默认关闭。源文有疑义就保留疑义，不靠无限重写“消除”不确定性。

## 本轮范围与实际取舍

| 方向 | 候选版状态 | 限制/取舍 |
|---|---|---|
| 忠实约束、少量双语前文、相关术语 | 已实现，不新增固定轮次 | 未证明三项各自有质量收益；不扩大原上下文或改变分批 |
| 术语冲突保留 | 已实现 | 无用户确认词条界面、专名/多义词完整分类体系 |
| 标准有限重点复核 | 保留并接入可选参考 | 仍不是全片语义审校 |
| 精修全片覆盖及候选核验 | 已实现三阶段与审计 | 全片旧设计实测发现误改，因此改为候选核验；新设计仍待整片质量验收 |
| 独立思考、精修模型与预算 | 已实现 | 同端点/凭据；账本不包含源字幕准备中的原有术语索引和ASR |
| 网络词义参考 | 已实现受控Brave适配器 | 只验模拟/故障；未有真实凭据验收，无来源信誉排名或查询改写 |
| 本地参考SRT | 已实现保守时间对齐与逐任务确认 | 不自动确认作品身份；纯中文不猜整体偏移 |
| 缓存、用量、恢复 | 已实现策略隔离、累计计数及响应回放 | 不支持删账本后仍保证不重付；不自动刷新已完成参考 |
| 发布 | 候选源码与暂存包 | 不覆盖生产程序，不声称正式质量转正 |

首版将模型和资源上限集中在现有设置页的“质量方案与参考”卡片，不再增设层层高级页面。没有建设大型作品知识库；参考记录只保存关联目标、词语、来源类型、URL/时间及必要摘录，不能当作完善的术语知识管理系统。

## 共享底稿的开发约束

- 忠实优先，保留否定、数量、条件、对象和不确定语气；不擅补性别、关系、身份和异常识别原句。
- 前方最近至多4条已完成底稿译文作为辅助，不能超过原上下文条数；前文错误不能压过当前原文，不读取后处理结果。
- 相关术语按源文筛选；英文使用词边界，冲突保留而非后写覆盖，不硬套词表。
- 保留结构化输出、目标ID和时间轴；不额外要求快速档输出长篇分析。
- 以上增强需质量对照。若无净收益或有明显回归，可独立撤回，不以“方案完整”要求全部保留。

分批边界调整、并发和加速不在本轮范围。只有实测错误集中在边界且现有增强无法解决，才另行讨论自然断点切分。

## 精修的最终采纳设计

**冻结底稿 → 全片提案 → 候选复核 → 定向否决检查 → 输出/待核对。**

第一阶段只提案，不立即覆盖；第二阶段以原文独立核验所有可操作候选，不传递第一阶段的理由，且只采纳两轮一致的候选；第三阶段仅允许回退已采纳修改，不引入新译法。没有合格候选的场景不增加无意义轮次；新疑义留报告，不循环到第一阶段。

模型必须返回目标ID、问题类型/严重性、可定位原文证据、候选译文、理由、引用ID及源文核对标记。目标、引用和结构校验不等于语义正确。纯风格偏好、无法确定的主语或异常ASR不自动改写。同模型二次核验也可能一起判断错误，必须保留人工质量门槛。

用户可将精修三项累计上限设0，按全片流程执行；每个逻辑窗口最多两次实际HTTP尝试，固定三个阶段，连续失败暂停。精修更愿意花费的含义是增加覆盖和核验，不是无限候选、无限反思或用完额度。

## 参考资料的开发约束

- 用户主动启用联网并确认隐私。只发源文中出现的必要短语，不按每句搜索，不自动下载整片字幕或字幕压缩包。
- 搜索摘要不可作为直接改译证据；读取正文、记录来源并标为未验证，模型将其视为不可信输入而非指令。
- 参考和质量译文存于质量版本，不污染共享底稿；失败降级、有限查询、重复与未知查询不自动重发。
- 本地参考先确认作品，保守对齐。时间匹配只能提示，已有翻译可能来自不同版本或本身有误。
- 初版不做作品身份搜索、站点信誉平台、知识库、来源自动刷新或通用检索插件系统。只有真实验收指出明显缺口再扩展。

## 验收与转正门槛

### 工程回归

保持统一离线入口，覆盖：配置迁移/思考偏好、跨档缓存隔离、底稿不可变、目标与证据合法、候选拒绝/确认/回退、完成与未完成区别、预算与两次尝试上限、取消/未知响应/回放、报告损坏、字幕归属、搜索降级与网络安全、本地参考错位、设置布局与更新回滚。

测试不得调用真实模型或读取生产配置；付费验证单独显式确认。最终从只含待提交文件的干净源码导出复验，避免开发目录漏文件。UI要区分96 DPI测试和用户175%缩放实际交互，截图不替代体验验收。

### 质量与成本

1. 冻结约200条带上下文的样本，至少两种源语言、两种对白类型，保留足够“原译已经正确”的条目检测误改。
2. 同源文、模型、配置比较1.1.0与增强快速档，再比较同一新底稿的标准/精修；分别记录联网开关。底稿三项增强要能单独归因，不把接口随机性当收益。
3. 能理解源语言的人工盲评记录严重错译、漏意、新误改、术语与阅读体验。模型可辅助整理，但不能自评即验收，改动数/覆盖率不能替代质量指标。
4. 快速档不新增固定请求轮次；至少5组成对交替计时，中位数增幅不超过10%作为工程目标，同时列最慢样本、输入/输出和重试。已完成的一组小素材计时只覆盖局部，不代表所有影片。
5. 精修应有可辨认的实质错误净减少，不能留有新严重误改。若收益不足，收紧或撤回自动修改，不用“更慢、更全面”证明更好。
6. 最终采纳策略至少运行两种语言、不同对白类型的两部完整作品，优先用已有字幕，记录覆盖、失败、恢复及真实用量；人工检查全部改动、抽查未改片段。
7. 使用真实Brave凭据核验限额、无结果、正文提取和资料对翻译的实际帮助，不以本机模拟接口代替联网验收。

10%与样本量是验收目标，不是宣称的收益。缺少合适素材、人工判读或真实服务条件时保持候选状态；不为转正无限消耗付费调用，也不自行放宽门槛。

## 交付边界

只提交源码、测试、原创素材、脚本和脱敏说明。生产程序、设置、识别/翻译缓存、密钥、影片和完整报告不进Git；旧回退文件归档而非删除。候选包有源码及二进制哈希，用户完全退出后用保护更新器安装。Git提交、二进制安装、真实质量认证分别报告，不能互相替代。

本轮不做播放器重构、实时字幕、自动批量重译历史库、局部音频重听、多模态全片、多供应商路由、多模型投票、自动训练、云端账号/计费或自动更新平台。
