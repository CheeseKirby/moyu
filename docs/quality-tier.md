# 翻译策略 1.2.0-rc.1：实现与验收

整理：2026-09-13（UTC）。**候选版本，尚未通过新增精修的完整语义质量验收。** 标准方案仍为质量档默认选择；新旧缓存与已安装程序保留。本文是当前策略、预算与证据的唯一维护入口。

## 三种使用方式

| | 快速档 | 质量·标准 | 质量·精修（候选） |
|---|---|---|---|
| 共享底稿 | 不思考，沿用现有分批 | 复用同策略底稿 | 复用同策略底稿 |
| 增强 | 原有规则修复 | 全片规则扫描、最多6个重点场景、有限修复 | 全片候选提案、候选复核、定向一致性检查 |
| 思考 | 关闭 | 可选，新配置默认关闭 | 可选，新配置默认开启 |
| 外部参考 | 不使用 | 可选 | 可选 |
| 成本取向 | 不增加固定模型轮次 | 有限重点检查 | 用户主动投入更多时间和调用，仍有终点 |

新底稿增加忠实约束（否定、数量、条件、对象与不确定语气）、前方至多4条已有中文参考、相关术语筛选与冲突保留。中文上下文不超过用户原设条数，设为0则不添加；质量后处理不回写底稿。术语冲突不靠后写覆盖，也不机械强制替换。未改批次切分、并发或识别架构。

旧设置迁移到标准方案，保留标准思考偏好；精修思考独立保存。联网默认关闭，切换快速档不清空质量偏好。设置页提供质量方案、参考SRT、独立搜索密钥、精修模型和上限；精修开始前再次确认模型、思考、源语言、联网及成本边界。精修模型只允许同一服务端点与凭据，不提供跨供应商路由。

## 标准方案：保留有限重点复核

全片本地规则扫描 → 可选参考准备 → 按风险和前中后时间分布选最多6个场景 → 定向修复。每场景最多35条、150秒，复核前后文默认各8条。疑似误听、残缺或必须核对原音的条目只提醒，不猜源文。

| 复核与修复累计限制 | 不思考 | 思考 |
|---|---:|---:|
| 模型请求（含失败与截断重试） | 10 | 10 |
| 活跃时间 | 180秒 | 480秒 |
| 输出额度预留 | 49,152 token | 131,072 token |
| 规则修复、建议修复 | 各最多1批，每批24条 | 同左 |

单次输入最多60,000字符，累计480,000字符。模型限制不含基础翻译、ASR、原有术语索引；参考预查有独立30秒累计联网时限，后续问题查证也受这30秒约束。后续查证时间可能同时计入模型复核活跃时间，因此不能将两项计时相加冒充独立账单。

## 精修：先验证再采纳，最后只能否决

1. **全片提案 refine。** 每条字幕进入且仅进入一个正式目标窗口；上下文出现不算覆盖。只读冻结底稿，输出原文证据、完整候选与疑点，**此轮不改译文**。
2. **候选复核 adjudicate。** 复核所有有可操作候选的场景，不仅复核疑难。请求仍以冻结原译为基准，只带候选文本/ID和必要查询短语，不带第一轮理由或其声称的证据，减少迎合。只有第二轮确认原译存在实质错误、原文证据可定位、引用有效，且候选文本与第一轮**完全一致**，才允许通过原有修复护栏后采纳。拒绝、不同译法、空候选和纯风格改写不自动采用。
3. **一致性检查 consistency。** 对已改条目、规则异常和术语冲突相关场景做一次检查。该轮**不得引入任何新改写**：有实质问题的已改条目只能回退冻结原译；新疑点保留在报告。不会回到第一轮或开启无限反思。

第一轮提出检索需求不代表必须依赖外部知识：第二轮若仅凭原文就能确定，可清空检索需求；第二轮仍要求外部查证却没有有效引用，则保留原译。不用缺少搜索密钥阻断本可依原文确定的否定纠错。

所有精修语义请求遵循精修思考设置；基础翻译仍不思考。同模型二次确认不是独立人工证明，完全一致门槛也可能漏掉有效修改。收尾回退优先避免新误改，可能牺牲纠错召回。

### 预算与恢复

- 精修时间、模型请求、输出预留三项的0表示不限累计额度，**不表示无限循环**。有上限时到限保留断点和已有结果。搜索0表示默认值，含义不同。
- 精修累计账本从源字幕就绪后创建，涵盖本次新底稿模型请求与三阶段精修；活跃时间也包括此后的参考等待。**源字幕准备/识别中的旧术语索引请求不在该账本内，ASR也不在内**；历史缓存不算本次新增费用。
- 每个基础/精修逻辑窗口跨重启最多两次实际HTTP尝试；截断倍增也占一次。连续两个窗口失败暂停，禁止重试相乘。无累计上限时仍有限单请求超时、输入长度和阶段终点。
- 请求前持久化用量预留；返回后持久化请求哈希和原始响应。应用状态落盘前崩溃，可零调用回放响应；结果未知的请求必须明确确认可能重复收费才重试。
- 重启不清零请求、输出预留、已记录活跃时间和窗口尝试次数。结果未知的中断补计等待时间至多300秒，是保守估算，不是服务商精确计时。
- 输出预留不等于实际token或金额；报告另记接口返回的prompt/completion/reasoning usage与缺失情况。没有输入+输出精确金额硬限额；取消连接不保证服务商停止收费。

## 网络与已有译文：可选、不可信的辅助资料

- 唯一搜索适配器为Brave Search，独立Windows凭据项；需要勾选联网并确认隐私。只搜索源文中出现的短语及语言/词义提示，不上传整片字幕给搜索引擎，也不自动下载字幕包。
- 标准默认最多6次搜索、累计联网30秒；精修默认30次搜索，可设至300次，每次搜索连同页面获取最多30秒，并受精修累计时限约束。预查最多用一半搜索额度，留给后续疑点。无查询则不发请求。
- 最多读取每次搜索前2个结果的正文，摘要不作为修改证据。记录URL、获取时间、摘录和查询状态，正文标为web-unverified，不声称来源已经可靠认证。
- 只按相关目标附加最多12项参考；网页内容被明确作为不可信资料而非指令。公共地址、端口、逐跳重定向、实际连接IP、类型、大小与超时受检查，搜索密钥不跟随重定向。失败/失网/缺密钥不自动重试付费查询，不阻断普通原文翻译。
- 本地参考SRT最多4MB、10,000条；以唯一且至少75%的时间重叠作为提示。仅在至少3个唯一原文锚点且80%偏移一致时平移，纯中文文件不猜偏移。时间匹配不等于作品匹配或译文正确。
- 参考SRT是全局选择，界面提醒换作品清空，**每个质量任务开始再次确认对应作品**。没有自动作品身份识别。
- 首版没有来源信誉排名、作品名搜索、查询改写、用户术语确认界面或证据主动刷新入口。补密钥不会静默刷新已完成的缓存；不要手动删账本来强迫重查。

本机未配置Brave搜索密钥，本轮只验证了模拟返回、安全边界和降级，**尚未验收真实联网检索**。参考正文与本地参考译文会随相关上下文发送给配置的模型服务，网络来源站点也会看到访问请求。

## 缓存、审计与报告

- 当前基础策略base-3-context-conflicts，复核策略review-5-verified-candidates。缓存按源字幕内容/时间轴、语言、端点、模型、上下文及策略分层；质量版本另含方案、有效思考、参考SRT内容哈希、术语与精修模型。
- 目录为源缓存下translations/<基础键>/<处理版本键>/。预算不进版本键，调高上限可在原计数上续做；切模型/策略/参考文件会产生新版本，可能重新付费。
- 旧缓存不删除。缺少当前底稿且检测到历史底稿时，流水线先确认迁移费用；共享源字幕不需重新识别。命令入口若没有确认回调会明确拒绝该迁移，不静默付费。
- 冻结底稿与修改journal分离，先写审计再更新状态；记录提案、未确认、采纳与收尾回退。最终采纳数只统计相对冻结底稿仍有变化的条目，回退不算提升。
- 完成标记校验状态、报告、参考文件和输出哈希；单纯输出字幕损坏可本地重建。状态/报告损坏、策略或底稿不一致时明确停止，不默认空状态重新付费。
- 标准limited-review-complete表示有限流程完成；partial表示未完或仍有问题。精修full-review-complete只表示三阶段均成功且目标覆盖完整，**不表示每句正确**。待核对、未采纳、预算停止及失败另列。
- 不覆盖没有本程序归属证据的用户字幕；私人字幕、报告、网页摘录、配置和路径不随Git发布。

## 验证记录与发布判断

### 离线回归

质量档65项断言；新增演进65项断言；翻译客户端7组；UI16组及独立DPI设置验证；检测器8组；更新器4组；另有核心11组、界面自检8组。套件覆盖重叠，不累加为产品功能数。统一入口及环境说明见[开发文档](development.md)。

新增覆盖包括两阶段确认、拒绝/不同候选、收尾回退/只记录、预算停在候选阶段不改译、候选续做、不可复用旧策略、付费响应回放、未知响应确认、有限重试、失网降级与参考对齐。UI本轮实际测得96 DPI，不能据此声称用户175%缩放已经验收。

日语小样本还暴露过“第一轮无必要检索请求阻止纯原文纠错”的问题，修复后才得到上表最终结果。英语样本在该检索门槛修补前运行，但无检索请求，不受该变更影响。没有将多个提示/护栏迭代的结果混成同一最终版本的全片验收。

**尚缺：最终三阶段策略的跨语言/跨类型两部整片验证、约200条冻结人工盲评、真实Brave搜索、新UI的175%实际交互。** 新底稿三项增强也未分别做质量消融对照。旧全片计时、采纳数、模型自评、覆盖率和规则清零均不能填补这些缺口。

因此本次交付为1.2.0-rc.1源码与本地候选更新包，不宣称新增精修已经是成熟、稳定优于标准的翻译方案；也不为赶正式版本继续无限付费试跑。正式转正门槛见[优化方案](translation-optimization-plan.md#验收与转正门槛)。
