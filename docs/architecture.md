# 架构与数据流

魔芋采用“播放器外部工作进程 + 原生桌面工作台 + 独立轻量检测器”。播放器保持播放职责；媒体读取、识别、翻译及字幕发布均由魔芋执行，不注入播放器插件。

## 处理流程

~~~text
拖入视频 / 确认播放器检测提示
  → 内容指纹与所选源语言
  → 旁置字幕 → 内嵌文本字幕 → 本地音频识别（按可用性选择）
  → 源字幕规则清理与识别状态
  → 按场景生成 / 复用基础译文（不思考）
  → 快速档规则修复，或质量标准有限复核 / 精修候选核验
  → 校验并保存处理版本、质量报告、完成记录
  → 视频旁双语字幕 + 字幕库归档
~~~

基础字幕与译文可复用；切换语言、模型或处理策略时隔离相关缓存。内容指纹服务于改名/移动后的复用，不是对任意两份媒体绝不冲突的形式化保证。

| 总流程 | Pipeline.cs | 编排识别、翻译、质量控制、缓存及发布 |
| 源字幕 | Recognition.cs、Srt.cs、SubtitleQuality.cs、SourceLanguages.cs | 获取与清理源字幕、分场景、语言隔离 |
| 模型协议 | DeepSeek.cs | 请求、结构校验、有限重试、取消与隐私日志 |

| 外部参考 | TranslationReferences.cs | 可选受控查询、本地SRT对齐、来源审计与网络边界 |
| 持久化 | Core.cs、TranslationCache.cs | 设置、内容指纹、原子 JSON、分阶段缓存和完成校验 |

以上主程序文件位于 src/。历史网页原型不参与编译，WinForms 不依赖网页运行时。

## 成本与故障隔离

- 质量档与基础翻译分阶段，避免将深度思考施加到每一个基础场景。规则扫描不调用模型，但术语索引、翻译和复核仍可能收费。
- 模型响应必须有合法目标条目；空正文或截断不能冒充成功。复核的失败与重试消耗累计预算，不在重启后清零。
- 部分复核失败时保留已有译文，并在报告及完成提示中说明未完成部分。报告损坏/缓存基线不一致时明确停止，而非静默重新付费。
- 原译文、质量版本与修改审计分离；被接受的修改先记录再更新状态，可在中断后回放。
- 用户取消不意味着服务商一定停止计费。对结果未知的中断请求不自动重付。

精修第一轮仅记录候选，第二轮确认一致候选才可采纳；第三轮只能回退已改条目或记录问题。参考内容不回写共享底稿，不将来源网页当作模型指令。精修账本从源字幕就绪后创建，不包括此前识别/术语索引。

详细状态与限额只有一个维护入口：[质量档设计](quality-tier.md)。

## 数据与隐私边界

| 本地数据 | 生命周期与发布边界 |
|---|---|
| Config/ | 设置及运行状态；保留，禁止提交 |
| Cache/ | 源字幕、识别断点、基础译文、质量版本和报告；用于复用，不作为临时垃圾批量清理 |
| Queue/、Logs/ | 任务与诊断；可能包含路径及任务信息，禁止提交 |
| hub/ 或自定义字幕库 | 用户归档；字幕正文不随源码发布 |
| Windows 凭据管理器 | 模型与Brave独立API Key；不复制进仓库或发布包 |
| 本地更新 / 回退目录 | 安装包、证据和旧程序；不随 Git 发布 |

可选搜索发送源文短语和语言/词义提示，来源网页接收访问请求；已有SRT及网页摘录会随相关上下文进入模型请求。搜索不上传整片字幕，不代表翻译阶段不上传字幕。

本地识别使用媒体音频；联网阶段会把源字幕、上下文、当前译文及必要术语发送到配置的模型端点。不要将项目描述为“字幕不出本机”或“全流程离线”。兼容 Chat Completions 的结构不保证任意服务商的模型、思考参数、JSON 返回与用量字段完全兼容。

## 现阶段非目标

不提供实时逐字字幕、播放器插件、云端账号/计费系统或通用模型代理；不自动猜测修正疑义源文，也不以 LLM 自评替代全片人工质量基准。当前交付聚焦可用的单机字幕处理闭环。
